长局自动性能日志 — 2026-10-26

使用方法
关闭旧游戏，运行 artifacts/longrun-diagnostics/RunBuildPew.exe，或从当前 Godot 工程重新 F5。
正常游玩即可，进入一局后自动开始记录，不需要一直开性能面板。
遇到持续掉帧时可以按一次 F3 留标记，同时保留原有三秒 F3 采样；不按也会自动捕捉持续慢帧。
暂停菜单的“性能日志”按钮可打开目录，F4 也可打开；F4 已在玩家设置中绑定其他操作时仍由原绑定处理。
结束后正常退出游戏，将目录中最新的 run-* 文件夹整体压缩提供，保留 session.json 和 part-*.jsonl。
也可以先在暂停菜单打开目录，再退出游戏、压缩该文件夹。每局独立保存，目录为 user://performance-logs。
暂停、奖励、装配和结算会留下状态事件；这些停留时间不计入战斗帧耗时。

记录内容
每秒：实际帧间隔的均值、P50/P95/P99/最大值、超过 16.67/33.33ms 的比例、主逻辑 CPU 时间。
战斗规模：敌人、可见敌人样本、友/敌弹样本、特效、拖尾、掉落、无人机、地雷、黑洞、毒区、幼虫等数量。
增长线索：节点/对象/资源、可用内存监视值、地图节点、生成任务、导航/碰撞/地形缓存、岩层网格与虫体池等规模。
上下文：游戏版本、六个关键脚本的 SHA256、渲染器、GPU、分辨率、刷新率、垂直同步、焦点、角色、任务、难度、装备及升级变化。
详细采样：每 15 秒记录约 400ms；连续三帧达到或超过 33.33ms 时记录约 1.5 秒，每 30 秒最多自动触发一次。
F3 标记会增加约三秒详细采样，原 F3 报告也嵌入同一局日志，便于整体提供。
CPU 分段包含主逻辑、绘制命令提交、AI、碰撞/弹体等已有计时点；分段有嵌套，不能直接相加。
实际帧间隔还受引擎、渲染和操作系统调度影响；这些 CPU 分段不等于 GPU 时间。
可见敌人和敌弹分类每次最多检查 4096 个，并写入实际检查数量；总数量仍记录完整容器大小。
Release 中无法获得的静态内存监视值写为 null，不把它当作零或推断为没有内存增长。

开销与保存
常规帧只累加时间和计数，每秒做一次汇总；详细分段仅在采样窗口内启用。
后台线程持有文件句柄、写盘、刷新和轮转，主线程只提交序列化后的记录；队列有容量上限，并记录错误与丢弃计数。
每秒刷新；正常退出等待队列写完并标记 closed。强制结束进程仍可能缺少最后少量记录，分析器可跳过损坏末行。
默认保留最近四局，每局最近三个 8MiB 分片，总量约 96MiB，另有文件头/元数据及单条记录边界的少量空间。
轮转只处理本记录器拥有的会话和固定日志文件名，不递归删除玩家另外放入的笔记或文件。
本轮没有为日志降低显示效果、减少弹量或怪数；日志不调用战斗 RNG，也不写入进化/设置/成绩存档。
日志保存在本机，不自动上传；不记录按键、截图、完整存档、用户姓名或项目/EXE 绝对路径。
测试和压力场景默认不启用，避免污染性能对比；需要时显式设置 RBPEW_RUNTIME_LOG=1。RBPEW_RUNTIME_LOG=0 可关闭。

读取与后续分析
python tools/analyze_runtime_log.py "路径/最新run文件夹或ZIP" --output artifacts/longrun-analysis.json
分析器使用 Python 标准库，可直接读取目录、单个 JSONL 或 ZIP，不解压执行压缩包内容。
输出最慢的秒级窗口、计数增长、采样阶段排名、装备变化和玩家标记，先对照真实后期时间段，再定位优化目标。
只对保留帧的均值做帧数加权；不会把每秒 P99 拼成一个虚假的全局 P99，阶段排名也注明嵌套与慢帧采样偏差。
