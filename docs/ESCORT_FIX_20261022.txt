洞穴护航：商队卡死、低帧率与任务提示修复 / 2026-10-22

现场与根因
用户在护航模式开局约 23 秒看到 19 FPS / 51.7ms，装配界面约 379 FPS，并反馈商队完全不动。
此前只测生存模式，未复现这一持续开局低帧率；本次按护航任务和四节装备补充复现。
原逻辑将开阔场景的全部运输船及其偏移包成半径 927px 的整体，尝试在洞穴里移动。
同时玩家开局在 x=960，旧商队中心在 x=0，超出了 600px 的启动范围；友船本身散在中心周围，界面未说明这个中心判定。
将玩家移到 x=240 后，商队满足启动条件，但整体无法穿过洞穴；15 秒仅偏移约 3px，护航更新平均耗时约 43ms。

修改后的洞穴玩法
商队在玩家附近的完整空区集合，保留普通/困难/噩梦原有的 7/6/4 艘、生命、损伤、72px/s 行驶速度与 600px 随行范围。
玩家沿终点箭头清敌、挖路；每艘船沿玩家实际走过的路线逐段跟随，使用自身 15px 碰撞半径。
路线有点数上限，会删除已经通过的尾部；不再对整个宽队形进行寻路和扫掠，也不穿墙瞬移。
离队停车，回来重新接上；跨墙返回不能建立直穿岩石的路径。领队死亡后，存活运输船沿原路逐步补位。
接近终点时允许商队走完最后一段，玩家可在安全区等候。至少一艘实际抵达才获胜，全部损失失败；存活奖励仍由源任务数据计算。
终点若落在岩石上，使用同一物理碰撞寻找可容纳运输船的安全位置。非洞穴护航保留原先自动前进方式。

任务可读性
友方运输船有绿色标记和“商队”标签；屏外商队与安全区有方向和距离。
护航专用提示显示存活数、实际路程进度、距离，以及集合、跟随、落后、离队等待和进站等状态。
提示明确说明至少一艘抵达获胜、全灭失败。路程进度单独显示，上方原有百分比继续表示威胁热度。
任务选择页补充靠近领航、清敌开路和失败规则，并保留每波敌群数据。
中英文在 1440×900、1280×720 实际渲染检查，不遮挡遭遇事件和技能面板。

原生实时性能
Godot 4.6.3 / Windows OpenGL Compatibility / GTX 1050 / 1440×900。
使用正式 main 场景、正常护航地图、原生 AI 与武器，安装 Tesla、EMP、Repair、Shield 四节装备。
开启 --debug，使用真实引擎 delta 和可见原生窗口，不传 --fixed-fps。
检查时提高角色和商队生命，保证持续观测；不代表用户当时的全部被动升级与交战历史。
