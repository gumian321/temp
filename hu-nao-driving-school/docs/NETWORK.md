# 联网与性能设计

- Godot ENet，单房主加一客人，UDP 27850；房主选择角色，另一人自动分配相反角色。
- 房主权威：车辆、资源、怒气、前摇、命中、修复、计时与胜负仅由房主推进。
- 物理固定 60 Hz，状态快照 30 Hz。通道 0 为有序不可靠输入（60 Hz），通道 1 为有序不可靠快照（30 Hz），通道 2 为可靠动作／房间消息／修复键按下松开。设计参考 [Godot 官方高层联机文档](https://docs.godotengine.org/en/stable/tutorials/networking/high_level_multiplayer.html)。
- 学员客户端使用相同纯运动函数预测，收到快照后回放未确认输入，上限 120 帧；教练客户端按约 100 ms 缓冲插值。车辆是平面运动模型，非 Godot 刚体，没有宣称完整刚体回滚或确定性锁步。
- 快照具有局号和单调 tick，重开清理预测历史；可靠动作有单调序号与局号，重复与过期动作丢弃。角色、类型、范围、NaN/Inf、输入数组长度均校验。
- 移动／副刹控制失联超过 350 ms 后松开；修复采用可靠按下／松开边沿，避免不可靠包缺口反复重置 1.5 秒进度；8 秒无输入／快照将连接返回房间。没有等待远端 frame 的同步屏障。
- 应用出站队列最多 256 项、预测队列 120 帧、插值缓冲 16 快照；队列溢出断开慢连接，不停住房主。ENet 抖动概率节流配置为 1000/32/0，由固定应用发送率和有界队列控制流量，避免抖动导致连续输入被误判松开。不设置 ENet 的额外字节节流（验证中它导致本地输入降频）；输入／快照由 60/30 Hz 应用节奏限制。正常快照编码约 0.7–0.9 KiB，目标总流量 < 50 KiB/s/方向；可靠操作只在按键边沿发送。
- `network.gd` 支持应用层延迟／抖动／不可靠消息丢失。集成测试另外通过普通 UDP 代理对所有 ENet 数据报施加单程 100±40 ms 延迟及 5% 丢包，包括可靠消息的底层重传。

## 性能预算（目标，未在真实 GPU 验收）

目标 60 FPS = 16.67 ms/帧；期望游戏规则＋联网 < 2 ms，CPU 场景/UI < 4 ms，GPU < 12 ms。60 Hz 规则与 30 Hz 快照是起始参数，不是所有机器的保证。输入／快照彼此独立，不因一次可靠整蛊等待重传而停住物理。

保留车辆 1,096,869 个三角面，其中 1,087,717 个不透明三角面原样合并为 22 个材质组；透明部分保持原网格。环境 700 个不透明 MeshInstance 合并为 26 组，保留 392,064 个三角面。合并发生于加载时，减少每帧 draw calls；不做游戏中连续网格重建。阴影会增加实际绘制三角面与调用。轻量模式关闭阴影／抗锯齿，降低 3D 像素数量；中文 HUD 保持原分辨率。

## 已知限制

- 物理是简化的平面车辆模型，没有变速箱、悬架、精细轮胎接地或原生刚体回滚。
- 预测是有限重放；丢包、迟到的副刹、碰撞会出现可见校正，不保证零抖动。只有两人可信局域网用途，不是互联网防作弊方案。
- 计时基于权威固定步长。在房主渲染极度跟不上时，模拟会变慢；软件渲染结果不能用来验收实时体验。
- 新增镜面不是实时环境反射；纸飞机、汽水和镜面倾斜为最小交互表现，没有人物骨骼动画。
- 房主离线不会迁移房主。断线退房后可重连，新开局不会恢复断线中的比赛。
